# 2026-03-06 Session 1 — Sandbox Component Debug + Dynamic Skill Loading

## Summary
Full debug of the sandbox component pipeline, fixing 4 critical rendering bugs that made sandbox components "barely working." Also built dynamic skill loading so pods fetch latest platform skills from the API on boot without needing container image rebuilds.

## Sandbox Bugs Found & Fixed

### Bug 1: CSS Extraction Missing (CRITICAL)
**File:** `Jarble-mvp/components/canvas/sandbox/sandboxCore.ts`
**Problem:** `sanitizeHtmlProp()` stripped `<style>` tags from the `html` prop but **threw away the CSS content**. LLMs constantly put CSS in `<style>` tags within the `html` prop, and it was all silently dropped. Result: completely unstyled sandbox components.
**Fix:** Extract `<style>` content into a new `css` return field, merge with existing `css` prop (extracted first, existing after for override priority).

### Bug 2: `<link rel="stylesheet">` Extraction Missing
**File:** `Jarble-mvp/components/canvas/sandbox/sandboxCore.ts`
**Problem:** Stylesheet `<link>` tags in html were stripped by DOMPurify without being captured. Common LLM pattern: `<link href="https://cdn.jsdelivr.net/npm/leaflet/dist/leaflet.css" rel="stylesheet">`.
**Fix:** Extract `<link>` tags as `@import url("...")` rules into the CSS output. Handles both `rel-first` and `href-first` attribute order.

### Bug 3: JS Scoping in IIFE
**File:** `Jarble-mvp/components/canvas/sandbox/sandboxCore.ts`
**Problem:** User JS ran inside `try { ${userJs} } catch(e) {...}` within an IIFE function. `const`/`let` declarations were block-scoped and invisible to the global auto-resize code that tries to access `renderer`/`camera`. Three.js sandboxes couldn't auto-resize.
**Fix:** User JS now injects via `document.createElement("script")` + `document.body.appendChild(s)` for global scope execution. Errors still caught by `window.onerror` handler.

### Bug 4: Library Loading Order
**File:** `Jarble-mvp/components/canvas/sandbox/sandboxCore.ts`
**Problem:** Libraries loaded in parallel via `forEach` + async script tags. No dependency guarantees. If library B depends on library A and B loaded first, crash.
**Fix:** Sequential loading via `loadNext()` waterfall pattern — each library starts loading only after the previous one completes.

## Dynamic Skill Loading Architecture

### Problem
Bot platform skills (`BOT_SKILLS` in `jarble-ui-server.js`) were baked into the container image. Updating skills required rebuilding the image and restarting all pods.

### Solution
Each pod fetches latest skills from the API on boot, with graceful fallback.

```
Pod Boot Flow:
1. MCP server starts with baked-in BOT_SKILLS (hardcoded fallback)
2. After 3s delay, fetch GET /debug/platform-skills from API
3. If success: merge fetched skills over baked-in, cache to PVC
4. If API unreachable: load from PVC cache (/data/config/platform-skills.json)
5. If no cache: use baked-in defaults
```

### Files Created/Modified
- **`jarble-api-main/src/skills/platformSkills.ts`** (NEW) — Reads `jarble-ui-server.js` at runtime, extracts `BOT_SKILLS` via brace-depth parsing + `new Function()` eval. Single source of truth.
- **`jarble-api-main/src/routes/debug.ts`** — Added `GET /debug/platform-skills` endpoint serving `{ version, updatedAt, skills }`.
- **`jarble-api-main/src/mcp/jarble-ui-server.js`** — Added `fetchAndMergeSkills()` + `loadCachedSkills()` on boot with 3s delay. Skills cache to `/data/config/platform-skills.json` on PVC.

### Update Flow
1. Edit skills in `jarble-ui-server.js` (one file, one place)
2. Redeploy API server
3. Pods fetch latest on next restart — no image rebuild needed
4. PVC survives pod kills, so cached skills persist

## Key Architecture Notes

### PVC Persistence
PVCs survive pod kills, restarts, and deletions. All `/data/` content persists:
- `/data/config/platform-skills.json` — cached skills
- `/data/config/openclaw.json`, `/data/config/soul.md` — deployment config
- `/data/skills/` — installed marketplace skills
- `/data/components/` — custom components
- `/data/services/` — hosted service code + manifest (auto-restarts on boot)
- `/data/workspace/` — saved artifacts

Only in-memory state is lost on pod kill.

### Sandbox Component Pipeline (Post-Fix)
```
LLM output (html/css/js/libraries props)
  → sanitizeHtmlProp(): extract <script>, <style>, <link> from html → js/css/libraries
  → buildDocument(): construct full HTML with CSP, theme, bridge API, heartbeat
  → Libraries load SEQUENTIALLY (dependency order preserved)
  → User JS executes at GLOBAL scope (const/let/var accessible globally)
  → Bridge API (window.jarble) for parent communication
  → Heartbeat watchdog: 5s ping, 15s kill timeout
```
