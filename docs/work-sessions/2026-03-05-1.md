# 2026-03-05 Session 1 — E2E Test Suite: Full Coverage & Real API Migration

## Summary
Wrote and debugged comprehensive Playwright E2E tests covering all major frontend features. Migrated all tests from broken tRPC mock approach to real API testing against 2 running deployments (test1, test2).

## Problem
- Existing E2E tests used individual `page.route("**/trpc/deployment.list*")` intercepts
- Frontend uses `httpBatchLink` which batches multiple tRPC queries into a single request (URL like `/trpc/proc1,proc2?batch=1`)
- Individual route intercepts never matched, causing all mock-dependent tests to fail

## Solution
Rewrote all tests to hit the real running API. Removed mock helpers (`mockComponentBrowse`, `mockServicesList`, `mockPublishService`, etc.) from test files. Tests are read-only — they navigate, fill forms, and verify UI without creating/modifying deployments.

## Key Fixes (Recurring Patterns)

### Strict mode violations
- `getByText("text")` matching parent button's aggregate text AND nested element text
- Fix: Use `.first()`, `exact: true`, or more specific locators (label-based, filter-based)
- Examples: "Monthly Credit Plan", "$5/mo", "Google AI", "Free" vs "Freemium", "Deploy" nav vs action button

### Element type mismatches
- Dashboard cards use `role="button"` div, not `<button>` elements
- `page.locator("button")` won't find them; must use `page.getByRole("button")`

### Form layout changes
- Publish form got a "Source Deployment" dropdown, shifting `.nth()` indexes
- Fix: Use label-based selectors instead of positional indexes

### tRPC batch link
- Created `e2e/helpers/trpc-mock.ts` (batch-aware mock helper with SuperJSON) but ultimately didn't need it since real API approach was simpler and more reliable
