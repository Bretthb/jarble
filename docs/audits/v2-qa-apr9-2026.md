### What was tested

- Compared `credits_charged` values across time periods
- Reviewed `modelPricing.ts` source for correctness

```
Most recent delegation (2026-04-09T14:08:10):  credits_charged = 7  (REAL COST)
All earlier delegations (pre-deploy):           credits_charged = 1  (OLD HARDCODED)
```

The most recent delegation shows `$0.07` which is realistic for a Claude Sonnet call (~500 input tokens + 100 output tokens at $3/$15 per 1M tokens). This confirms the `modelPricing.ts` service is working.

### Code review findings
- `modelPricing.ts`: Clean implementation with 1h TTL cache, OpenRouter API bulk fetch, conservative fallback table for top models.
- `calculateHopCostCents()`: Correctly accounts for input, output, cache read, and cache write tokens. Rounds up to nearest cent with `Math.max(1, Math.ceil(totalUsd * 100))`.
- `flowDelegation.ts:1007-1018`: Properly wraps cost calculation in try/catch with fallback to 1 cent if it fails.

### Concern
- The `Math.max(1, ...)` floor means free models or very cheap calls will always show at least 1 cent. This is a reasonable conservative default but could mislead users about actual costs.

## 3. A2A Delegate Tool (PR #106) -- WARN

### What was tested
- Checked `jarble-ui-server.js` source in the deployed API image
- Inspected bot pod file system via kubectl exec
- Reviewed `openclaw.ts` renderConfigs for delegation-tools.json generation

### Results

**MCP server (in API image)**: Has `a2a_delegate` tool (9 references found)
- Tool loading from `delegation-tools.json` at `/data/config/delegation-tools.json`
- File watcher for live reloading
- Proper dispatch in `executeTool()` switch

**Bot pod (t2 at dep-f30qkp1rzy1x)**: 
```
/data/config/ contains:
  .env
  mcp/jarble-ui-server.js
  openclaw.json
  soul.md
  subagent-tools.json
  (NO delegation-tools.json)
```

**Root cause of missing delegation-tools.json**:
The `renderConfigs()` in `openclaw.ts` on the current HEAD (feature branch) does NOT include the `a2a_delegate` tool generation code -- it only generates legacy `delegate_to_{slug}` tools. However, the deployed image (from develop) DOES have the code. The issue is that configSync has not been triggered since the pods were recreated to write the file.

The MCP server gracefully handles the missing file:
```js
const DELEGATION_TOOLS = [];
try { DELEGATION_TOOLS = JSON.parse(fs.readFileSync(DELEGATION_TOOLS_PATH, "utf-8")); }
catch(e) { /* logs warning, continues with empty array */ }
```

This means delegation still works via the legacy `jarble_delegate` fenced block path (which is API-side, not MCP-tool-side).

### Action needed
- Trigger configSync for t2 to generate `delegation-tools.json`
- OR restart the pod (the init container runs configSync on startup)

## 4. Three-Tier Memory (PR #109) -- FAIL (Critical)

### What was tested
- Searched for `core_memory_read`, `core_memory_write`, `archival_insert`, `archival_search` in:
  - Local HEAD of `jarble-ui-server.js`
  - Deployed API image MCP server
  - Bot pod MCP server (`/data/config/mcp/jarble-ui-server.js`)
- Verified commit history to trace where the code was lost

### Results

**ALL three-tier memory code is MISSING from HEAD and production.**

The commit `6d667fb` (feat(memory): three-tier memory Phase 1) added 228 lines to `jarble-ui-server.js` including:
- `core_memory_read` / `core_memory_write` tools
- `archival_insert` / `archival_search` / `archival_list` / `archival_forget` tools (canonical names)
- Backward-compatible aliases for `store_memory` / `recall_memory` / `list_memories` / `forget_memory`
- `archival.json` migration from `store.json`
- `/data/memory/` directory for core blocks

**Root cause**: The merge commit `1afd806` ("merge: resolve conflicts from develop into three-tier-memory PR") resolved conflicts in `jarble-ui-server.js` by taking the develop side, which did NOT have the three-tier memory additions. All 228 lines of memory tool code were dropped.

```
git show 6d667fb:...jarble-ui-server.js | grep -c "core_memory"  => 5
git show HEAD:...jarble-ui-server.js     | grep -c "core_memory"  => 0
git show 6d667fb:...jarble-ui-server.js | grep -c "archival"     => 21
git show HEAD:...jarble-ui-server.js     | grep -c "archival"     => 0
```

Similarly, the `a2a_delegate` tool generation in `openclaw.ts` (from PR #106) was also lost in the merge:
```
git show ff6108a:...openclaw.ts | grep -c "a2a_delegate"  => 7+
git show HEAD:...openclaw.ts    | grep -c "a2a_delegate"  => 0
```

### Impact
- Bots cannot use structured memory tools (core_memory_read/write)
- Legacy store_memory/recall_memory aliases may or may not work depending on which MCP server version is deployed
- The archival rename migration (store.json -> archival.json) is not in effect
- The `a2a_delegate` tool generation in renderConfigs is not on the feature branch HEAD

### Remediation
Re-apply the three-tier memory changes from commit `6d667fb` to `jarble-ui-server.js` and the `a2a_delegate` generation from `ff6108a` to `openclaw.ts`. Both are straightforward cherry-pick/rebase operations.
